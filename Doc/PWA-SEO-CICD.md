## Progressive Web App (PWA)

### PWA Architecture

The PWA layer is powered by **[vite-plugin-pwa](https://vite-pwa-org.netlify.app/)** (built on Workbox) and integrates directly into the Vite build pipeline.

```
frontend/
├── vite.config.js          ← VitePWA plugin config (manifest + Workbox)
├── public/
│   ├── pwa-192x192.png     ← Required icon (add manually — see checklist)
│   ├── pwa-512x512.png     ← Required icon (add manually — see checklist)
│   ├── hero.png            ← Used as apple-touch-icon
│   └── manifest.webmanifest← Auto-generated by vite-plugin-pwa at build time
└── src/
    └── main.jsx            ← SW registration via registerSW() is auto-injected
```

At build time, `vite-plugin-pwa` generates:
- `dist/manifest.webmanifest` — the Web App Manifest
- `dist/sw.js` — the Workbox service worker
- `dist/workbox-*.js` — Workbox runtime chunks

### Service Worker & Caching Strategies

All caching is defined in `vite.config.js` → `VitePWA({ workbox: { runtimeCaching: [...] } })`.

#### Strategy Matrix

| Resource Type | Strategy | Cache Name | TTL | Max Entries |
|--------------|----------|------------|-----|-------------|
| Pre-cached app shell (JS/CSS/HTML) | **Cache First** (precache) | precache-v2 | Forever (until version change) | — |
| `/api/*` (local proxy) | **Network First** | api-cache-v1 | 24 h | 200 |
| `hireready-9lkl.onrender.com/api/*` | **Network First** | remote-api-cache-v1 | 24 h | 200 |
| Google Fonts CSS | **Stale While Revalidate** | google-fonts-stylesheets-v1 | — | — |
| Google Fonts files | **Cache First** | google-fonts-webfonts-v1 | 1 year | 30 |
| Unsplash images | **Cache First** | unsplash-images-v1 | 30 days | 60 |
| Cloudinary media | **Cache First** | cloudinary-media-v1 | 30 days | 100 |

#### Strategy Explanations

**Network First** — Always try the network first; serve from cache only when offline.
- Ideal for API data that must be fresh when online.
- `networkTimeoutSeconds: 10` prevents long spinner when server is slow.

**Cache First** — Serve from cache immediately; network only if not cached.
- Ideal for immutable/versioned assets (fonts, images with long TTLs).
- Never used for API endpoints.

**Stale While Revalidate** — Serve from cache instantly, then update cache in background.
- Ideal for resources that can be slightly stale (e.g., Google Fonts CSS).

### Offline Support

The entire app shell (HTML, JS bundles, CSS) is pre-cached during SW installation. When offline:
- The SPA loads normally from cache.
- API calls fail gracefully (UI should show "offline" state — see implementation below).
- Previously fetched API data is served from `api-cache-v1`.

#### Recommended: offline UI

Add this hook to key pages that fetch API data:

```jsx
// src/hooks/useNetworkStatus.js
import { useState, useEffect } from 'react';

export function useNetworkStatus() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);
  useEffect(() => {
    const on = () => setIsOnline(true);
    const off = () => setIsOnline(false);
    window.addEventListener('online', on);
    window.addEventListener('offline', off);
    return () => { window.removeEventListener('online', on); window.removeEventListener('offline', off); };
  }, []);
  return isOnline;
}
```

### Install Prompt Lifecycle

`vite-plugin-pwa` with `registerType: 'autoUpdate'` handles:

1. **Registration** — SW registers automatically on first load.
2. **Update** — When a new SW is deployed, it skips waiting and claims clients automatically (`skipWaiting: true`, `clientsClaim: true`).
3. **Install banner** — The browser shows the native install banner when PWA criteria are met (HTTPS, valid manifest, SW active, ≥30s engagement).

#### Optional: Custom Install Button

```jsx
// src/hooks/usePWAInstall.js
import { useState, useEffect } from 'react';

export function usePWAInstall() {
  const [prompt, setPrompt] = useState(null);

  useEffect(() => {
    const handler = (e) => { e.preventDefault(); setPrompt(e); };
    window.addEventListener('beforeinstallprompt', handler);
    return () => window.removeEventListener('beforeinstallprompt', handler);
  }, []);

  const install = async () => {
    if (!prompt) return;
    prompt.prompt();
    const { outcome } = await prompt.userChoice;
    setPrompt(null);
    return outcome; // 'accepted' | 'dismissed'
  };

  return { canInstall: !!prompt, install };
}
```

## Advanced SEO

### Why SEO matters for a React SPA

React SPAs render entirely in the browser (client-side rendering). Without intervention:
- Search engine crawlers see a near-empty HTML shell.
- Social media scrapers get no metadata for link previews.
- Per-page titles/descriptions are identical.

**Our solution:**
1. **`index.html`** — comprehensive static meta tags for the home page and default crawl.
2. **`SEO.jsx`** component (react-helmet-async) — per-page dynamic meta injection.
3. **Structured data** (JSON-LD) — rich results in Google Search.
4. **`robots.txt`** — tell crawlers what to index.
5. **`sitemap.xml`** — tell crawlers every public URL.

> **Future upgrade:** For perfect SEO, consider [React Router + Vite SSR](https://reactrouter.com/start/framework/rendering) or a Static Site Generation approach. Client-side SEO is good enough for most use cases but SSR guarantees crawlers see full content.

### Meta Tag Strategy

Each page should have unique, targeted meta tags. Hierarchy:

```
index.html (global defaults)
  └── SEO.jsx (per-page overrides via react-helmet-async)
```

#### Core Tags (every page)

```html
<title>Page Title | AdaptLearn</title>
<meta name="description" content="150–160 chars, unique per page" />
<meta name="keywords" content="comma, separated, relevant, keywords" />
<link rel="canonical" href="https://hireready-9lkl.onrender.com/page-path" />
<meta name="robots" content="index, follow" />
```

#### Title Tag Best Practices

| Rule | Example |
|------|---------|
| 50–60 characters | ✅ `Browse Tech Jobs | AdaptLearn` (33 chars) |
| Primary keyword first | ✅ `Skill Gap Analysis Tool — AdaptLearn` |
| Brand at end | ✅ `AI Learning Roadmap | AdaptLearn` |
| Unique per page | ✅ Each page has a different title |
| Never keyword-stuff | ❌ `Jobs Jobs Jobs Free Jobs AdaptLearn` |

#### Description Tag Best Practices

| Rule | Guidance |
|------|---------|
| 150–160 characters | Longer gets truncated in SERPs |
| Include primary keyword | Naturally, not forced |
| Include a CTA | "Sign up free", "Browse 500+ roles" |
| Unique per page | Duplicate descriptions = ranking penalty |
| Accurate preview | Describe what the page actually contains |

### Structured Data (Schema.org JSON-LD)

Structured data enables **rich results** in Google Search (FAQ dropdowns, job listings, breadcrumbs, star ratings).

#### Implemented Schemas

| Schema Type | Location | Rich Result Type |
|------------|----------|-----------------|
| `WebApplication` | `index.html` | App listing |
| `Organization` | `index.html` | Knowledge panel |
| `BreadcrumbList` | `index.html` | Breadcrumb trail |
| `FAQPage` | `index.html` | FAQ accordion in SERPs |
| `ItemList` + `JobPosting` | `SEO.jsx` buildJobListingSchema() | Job cards |
| `Course` | `SEO.jsx` buildCourseSchema() | Course rich result |

#### JSON-LD vs Microdata

We use **JSON-LD** (Google's recommended format) — placed in `<script type="application/ld+json">` tags in `<head>`. It does not require changes to HTML structure.

#### Example: Adding JobPosting rich results to the Jobs page

```jsx
// frontend/src/pages/JobsPage.jsx
import SEO, { buildJobListingSchema } from '../components/SEO';

export default function JobsPage() {
  const { data: jobs } = useJobs();

  return (
    <>
      <SEO
        title="Browse Tech Jobs"
        description="Explore hundreds of curated tech job listings matched to your skill profile. Filter by role, skills, and location."
        path="/jobs"
        keywords="software engineer jobs, ML engineer jobs, product manager jobs, tech careers India"
        structuredData={jobs ? buildJobListingSchema(jobs) : null}
      />
      {/* ... rest of page */}
    </>
  );
}
```

#### Example: Per-page breadcrumb

```jsx
import SEO, { buildBreadcrumbSchema } from '../components/SEO';

<SEO
  title="Your Dashboard"
  description="View your skill gap report, learning roadmap, and course progress."
  path="/dashboard"
  noIndex={true}   // private page — don't index
  structuredData={buildBreadcrumbSchema([
    { name: 'Home', path: '/' },
    { name: 'Dashboard', path: '/dashboard' },
  ])}
/>
```

> **Validate:** https://search.google.com/test/rich-results

### Per-page SEO with `SEO.jsx`

`frontend/src/components/SEO.jsx` wraps **react-helmet-async** and provides:

- Dynamic `<title>`, `<meta>`, OG, Twitter tags
- `noIndex` flag for private/auth pages
- Inline structured data injection
- Helper functions: `buildJobListingSchema()`, `buildCourseSchema()`, `buildBreadcrumbSchema()`

#### Usage

```jsx
import SEO from '../components/SEO';

export default function MyPage() {
  return (
    <>
      <SEO
        title="Page Title"                         // → "Page Title | AdaptLearn"
        description="150-160 char description"
        path="/my-page"                            // for canonical URL
        keywords="relevant, keywords"              // optional
        image="https://…/custom-og.png"           // optional, defaults to og-image.png
        imageAlt="description of image"            // optional
        type="website"                             // og:type, default "website"
        noIndex={false}                            // true for private pages
        structuredData={{ "@context": "…" }}       // optional JSON-LD object
      />
      {/* page content */}
    </>
  );
}
```

### robots.txt

Located at `frontend/public/robots.txt` — served at `https://…/robots.txt`.

**Key rules:**
- Public pages (`/`, `/jobs`, `/about`, `/contact`) — allowed for all bots
- Private routes (`/dashboard`, `/profile`, `/admin`, `/api`) — disallowed
- Aggressive bots (Ahrefs, Semrush, DotBot) — fully blocked
- Sitemap URL declared for all crawlers

> **Important:** After deploying, verify at https://search.google.com/search-console/robots-testing-tool

### XML Sitemap

Located at `frontend/public/sitemap.xml` — served at `https://…/sitemap.xml`.

**Structure:**
- `changefreq: daily` for `/jobs` (content updates frequently)
- `changefreq: weekly` for `/` 
- `changefreq: monthly` for about/contact/auth pages
- `priority: 1.0` for home, `0.9` for `/jobs`, `0.5` for auth pages
- Image sitemap extension for home page hero image

**Submitting to search engines:**
1. Google Search Console: Sitemaps → Add `https://hireready-9lkl.onrender.com/sitemap.xml`
2. Bing Webmaster Tools: Submit sitemap URL
3. The `robots.txt` already declares the sitemap URL automatically

**Keeping the sitemap updated:**
For a static SPA, update `sitemap.xml` manually when adding public pages. For dynamic content like individual job pages, generate the sitemap server-side or via a build script.

### Core Web Vitals

Google uses [Core Web Vitals](https://web.dev/vitals/) as a ranking signal.

| Metric | Good | Needs Improvement | Poor |
|--------|------|-------------------|------|
| **LCP** (Largest Contentful Paint) | ≤ 2.5s | 2.5–4.0s | > 4.0s |
| **INP** (Interaction to Next Paint) | ≤ 200ms | 200–500ms | > 500ms |
| **CLS** (Cumulative Layout Shift) | ≤ 0.1 | 0.1–0.25 | > 0.25 |

**Current optimisations in place:**
- Vite code-splitting (automatic per-route chunks)
- Lazy loading routes via React.lazy + Suspense (recommended addition)
- `preconnect` and `dns-prefetch` hints in `<head>`
- Immutable cache headers for hashed JS/CSS assets
- Gzip compression in nginx
- Hero video uses `preload="none"` (implicit — doesn't block LCP)

**Recommended additions:**

```jsx
// App.jsx — lazy load all routes
import { lazy, Suspense } from 'react';
const DashboardPage = lazy(() => import('./pages/DashboardPage'));
// Wrap all lazy components in <Suspense fallback={<Spinner />}>
```

**Measure:** https://pagespeed.web.dev/

### nginx SEO & Security Headers

The updated `nginx.conf` adds:

| Header | Value | Purpose |
|--------|-------|---------|
| `X-Frame-Options` | `SAMEORIGIN` | Prevent clickjacking |
| `X-Content-Type-Options` | `nosniff` | Prevent MIME sniffing |
| `X-XSS-Protection` | `1; mode=block` | Legacy XSS filter |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Privacy + referrer control |
| `Permissions-Policy` | camera=(), mic=(), geo=() | Disable unused APIs |
| `Content-Security-Policy` | Comprehensive allowlist | Block XSS/injection |
| `Strict-Transport-Security` | `max-age=31536000` + preload | Force HTTPS |

**CSP note:** The current CSP allows `unsafe-inline` and `unsafe-eval` for React compatibility. For stricter hardening, use a nonce-based CSP with SSR.

**Service Worker headers:**
- `sw.js` and `workbox-*.js` are served with `no-cache` — this is critical. If the SW itself is cached, users never receive updates.

### CI Workflow (`ci.yml`)

**Triggers:** push or PR to `main` or `develop`

**Concurrency:** New pushes cancel in-progress CI runs for the same branch (fast feedback).

#### Jobs

| Job | Runner | Steps |
|-----|--------|-------|
| `frontend` | ubuntu-latest | checkout → node setup → `npm ci` → **lint** → **build** → upload artifact |
| `backend` | ubuntu-latest | checkout → node setup → `npm ci` → **tsc --noEmit** → **build** → upload artifact |
| `ml-service` | ubuntu-latest | checkout → python setup → `pip install` → **flake8** → **pytest** |
| `docker-smoke` | ubuntu-latest | checkout → create .env → `docker compose build` → `docker compose up` → health check → `docker compose down` |

The `docker-smoke` job runs only on `push` (not PR from forks, for security) and requires all three previous jobs to pass.

#### Artifacts

Build artifacts are uploaded for 7 days:
- `frontend-dist` — the compiled React app (`/dist`)
- `backend-dist` — compiled TypeScript (`/dist`)

These can be downloaded from the Actions run page for debugging.

### CD Workflow (`cd-render.yml`)

**Triggers:** push to `main` only

**Environment:** `production` (add GitHub Environment with required reviewers for extra protection)

**Steps:**
1. Trigger Render deploy hook for the main service (backend + frontend)
2. Optionally trigger a separate ML service deploy hook
3. Poll `GET /api/health` every 30 seconds for up to 6 minutes

#### Setting up Render Deploy Hooks

1. Go to Render Dashboard → your service → Settings → **Deploy Hooks**
2. Copy the deploy hook URL
3. In GitHub → Settings → Environments → `production` → **Variables** (not secrets — these are not sensitive):
   - `RENDER_DEPLOY_HOOK_MAIN` — main service hook URL
   - `RENDER_DEPLOY_HOOK_ML` — ML service hook URL (optional)

> ⚠️ Deploy hooks are URLs that trigger deploys when POSTed to. Treat them as moderately sensitive — use environment variables (not secrets) so they appear in logs when needed.

### Docker Publish (`docker-publish.yml`)

**Triggers:**
- Push of a version tag matching `v*.*.*` (e.g., `v1.0.0`)
- Manual `workflow_dispatch` with a custom tag

**Registry:** GitHub Container Registry (`ghcr.io`)

**Platforms:** `linux/amd64` + `linux/arm64` (via QEMU + Buildx)

**Tag patterns:**

| Input | Generated Tags |
|-------|---------------|
| Tag `v1.2.3` | `1.2.3`, `1.2`, `latest` |

**Layer caching:** GitHub Actions Cache (GHA) is used for fast rebuilds.

```bash
# 1. Ensure main is clean and CI passes
git checkout main && git pull

# 2. Tag and push
git tag v1.0.0
git push origin v1.0.0
```

This triggers `docker-publish.yml`, builds all images, pushes to GHCR, and creates a GitHub Release with pull instructions.

### Security Scan (`security-scan.yml`)

**Triggers:** push to main/develop, PRs, every Monday at 03:00 UTC, manual dispatch

#### Scans included

| Tool | Scope | What it finds |
|------|-------|--------------|
| **CodeQL** (JS/TS) | frontend + backend | SQL injection, XSS, prototype pollution, path traversal, hardcoded secrets |
| **CodeQL** (Python) | ml-service | Command injection, SQL injection, path traversal |
| **npm audit** | frontend + backend | Known CVEs in npm dependencies |
| **pip-audit** | ml-service | Known CVEs in Python packages |
| **Gitleaks** | Entire repo history | Accidentally committed secrets (API keys, tokens, passwords) |

Results appear in the **Security** tab → Code scanning alerts.

#### Handling alerts

1. `npm audit fix` — auto-fix low/moderate issues
2. `npm audit fix --force` — fix breaking changes (test thoroughly)
3. For false positives: add a `.gitleaks.toml` config or CodeQL query filter

## Troubleshooting

### PWA

**Service worker not updating:**
- Clear site data in DevTools → Application → Clear storage
- Check that nginx serves `sw.js` with `no-cache` headers
- Verify `skipWaiting: true` and `clientsClaim: true` in Workbox config

**Install prompt not showing:**
- App must be served over HTTPS (or localhost)
- Manifest must be valid (check DevTools → Application → Manifest)
- User must have visited twice with 5+ minutes between visits (Chrome heuristic)
- Must have valid 192×192 and 512×512 icons

**Offline mode not working:**
- Check DevTools → Application → Cache Storage for `precache-v2`
- Verify `globPatterns` includes `**/*.{js,css,html}`
- Make sure SW is activated (not just installed) — toggle "Skip waiting" in DevTools

### SEO

**Google not indexing pages:**
- Use GSC URL Inspection tool
- Ensure no `noindex` meta tag on public pages
- Check robots.txt is not blocking Googlebot
- Submit sitemap in GSC

**Structured data errors:**
- Validate at https://search.google.com/test/rich-results
- Common issue: missing required fields (name, url, description)
- Check for JSON syntax errors (trailing commas, unescaped characters)

**OG image not showing on social share:**
- Image must be publicly accessible (not blocked by auth)
- Minimum 200×200, recommended 1200×630
- Facebook cache refresh: https://developers.facebook.com/tools/debug/
- Twitter cache refresh: append `?nocache=1` or use the Card Validator

### GitHub Actions

**CI fails on `npm ci`:**
- Delete `package-lock.json` locally, run `npm install`, commit updated lock file
- Ensure Node version in workflow matches local version

**CD deploy never completes health check:**
- Render free tier cold-starts can take 2–5 minutes
- Increase `sleep 60` in the wait step or raise `MAX` retries
- Check Render dashboard for deploy errors

**Docker build fails `linux/arm64`:**
- QEMU emulation is slow; consider building arm64 only on tagged releases
- Some npm packages with native bindings may fail on arm64 in emulation

**Gitleaks false positive:**
- Add a `.gitleaks.toml` at the repo root to allowlist specific patterns:
  ```toml
  [allowlist]
    regexes = ["EXAMPLE_NOT_A_SECRET"]
  ```
